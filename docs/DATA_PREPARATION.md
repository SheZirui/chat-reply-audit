# 数据来源与输入准备

[返回首页](../README.md) · 下一步：[完整分析与复核流程](WALKTHROUGH.md)

本项目只分析已经合法取得、且使用者有权处理的双人聊天 CSV/JSON，不提供聊天账号访问、进程读取、密钥提取或数据库解密的操作说明，不推荐特定第三方获取工具。

> [!WARNING]
> 数据获取可能涉及高风险第三方软件和其他人的资料。拥有账号或文件不等于参与者已经同意分析，也不证明来源合法、完整或安全。风险说明见[数据获取风险说明](HIGH_RISK_EXPORT.md)；它不构成对任何获取方式的推荐或安全认证。

## 先选择你现在的情况

| 手里有什么 | 下一步 |
|---|---|
| 只有手机或电脑聊天软件 | 可先使用官方备份保住记录；本项目不提供批量获取步骤，可使用虚构演示或经同意的小范围手工样本 |
| 只有官方备份包 | 留作来源平台支持的恢复用途；不能改扩展名交给本项目分析 |
| 已合法取得、获准处理的 CSV/JSON | 按本页核对字段、范围和完整性，匹配后直接统计 |
| 只有数据库或其他不可读文件 | 本项目不直接接收，不提供转换或解密指令；不要上传给模型或代处理服务 |
| 只有 HTML、TXT、截图 | 当前程序不直接解析。只能在本机手工核对并整理获准处理的小样本，不能猜测缺失时间或顺序 |

## 1. 下载项目与放置私密文件

在 GitHub 仓库选择 **Code → Download ZIP**，解压后在项目根目录打开 PowerShell。安装 Python 3.10+，运行 `python --version` 确认可用。Windows 只有 `py` 时，可将下文 `python` 替换为 `py -3`。本项目不需要安装第三方 Python 依赖。

建议代码与真实数据分开存放：

```text
你的专用工作目录/
├── chat-reply-audit/        通用代码与虚构演示
└── private-chat-data/      获准处理的输入与私密报告
```

不要在共同上层初始化 Git，不要把真实数据放入已开启云同步的目录。目录分开不是权限隔离，本项目的 .gitignore 也不会保护其他仓库或上层目录。

在项目根目录执行：

```powershell
New-Item -ItemType Directory -Force ../private-chat-data/input
New-Item -ItemType Directory -Force ../private-chat-data/output
```

这些命令只创建目录，不读取聊天软件。后续相对路径均以项目根目录为起点。

## 2. 官方备份、迁移与完整性是三件事

来源平台的官方备份与迁移用于其支持的数据保存、恢复或设备迁移，不等同本项目需要的可读 CSV/JSON。以该平台实际版本和官方说明为准；不要假设备份完成就已经把全部手机记录合并进电脑可查询消息。

对于已经取得并获准分析的文件，在本机与原会话核对最早／最近日期、几个中间日期和消息方向。整月空白可能确实没有聊天，也可能是历史不完整；媒体占位符不代表媒体内容已经可读。记录已知缺失范围和观察截止时间，报告只能代表实际输入，不能证明全部历史完整。

不要为核对完整性而把原始库、联系人列表、密钥或整段聊天上传给在线模型。

## 3. 没有可读文件时的小样本选择

没有可读输入，不必为了运行分析而尝试第三方提取或解密。可以直接运行 examples/ 中的完全虚构演示；或者在聊天参与者同意后，从自己可见的会话手工核对一个小范围的时间戳与发送方向。

下面是完全虚构的最小 CSV：

```csv
timestamp,sender
2030-01-01 09:00:00,A
2030-01-01 09:20:00,B
2030-01-01 09:22:00,A
```

用本机文本编辑器另存为 UTF-8 CSV。A/B 含义自行记录，不放真实姓名；每行应是一条实际核对过的消息。仅选一段连续范围，保留范围内全部有效消息，不能只挑几条“晚回”的消息来算总体平均。看不清精确时间、遇到加载缺失或顺序不确定时，不补造记录；在说明中标注局限。

只有 timestamp/sender 可以统计间隔，不能据此做语义上下文复核。小样本不代表整个聊天，更不能代表整段关系；手工抄录、截图与 OCR 也可能出错或泄露隐私。

## 4. 检查格式，不必让模型看真实正文

对已经合法取得并获准处理的文件，用本机编辑器查看表头，支持：

```csv
timestamp,sender,kind,message_id,conversation_id,text
```

或文档规定的中文列：

```csv
时间,会话,发送者,是否我发送,类型,内容,server_id,local_id,分片
```

中文方向必须是“是／否”，分别映射本人 A／另一方 B。支持 UTF-8 或带 BOM 的 UTF-8。不要用 Excel 直接打开再覆盖原始文件，以免时间、长 ID 或正文被转换。

JSON 需为标准消息对象数组或含 messages 数组的对象；同名扩展名不能证明字段兼容。详细结构见[输入格式](../references/input-format.md)。

字段不匹配时，可以只把表头、自己编的两行虚构数据、方向字段和时间单位说明交给 Codex，要求写一个只处理已有可读 CSV/JSON 的本机转换脚本。转换不包含账号访问、提取或解密；真实内容不需要出现在模型上下文中。

```text
请根据字段说明与虚构样例编写本机 CSV/JSON 格式转换脚本。不要打开真实聊天、数据库或密钥，不做账号访问、提取或解密。明确单会话筛选、时间单位、发送方向、系统消息和稳定消息 ID；未知含义先问，不猜测。运行只输出条数、日期范围与格式错误行号，不输出真实正文。
```

提示词不是沙箱。若不允许正文进入在线模型，请自己运行审查过的程序，并使用实际权限或隔离环境约束数据访问；切换工作目录不等于禁止读取其他位置。

## 5. 把一个可读文件交给本机统计

仅将已获准处理的一个双人会话保存为 `../private-chat-data/input/chat.csv`。不附带数据库、密钥、整账号目录或其他会话。

按[完整流程](WALKTHROUGH.md)运行 analyze。只需要平均间隔和长间隔候选时，无需正文或模型复核；需要语义复核时，另行确认参与者同意和内容范围。

## 6. 这条链路具体暴露了什么

| 环节 | 本机产物 | 外部发送 |
|---|---|---|
| 整理已有输入 | CSV/JSON 及本机副本 | 本项目不负责数据获取；来源软件另有边界 |
| analyze | 时间、计数、摘要与文件指纹 | 本项目命令不联网，其他软件或 Agent 有各自边界 |
| prepare-review／review-workbench | 含正文的候选 JSON 与离线 HTML | 命令本身不联网；交给在线 Agent 查看时，片段进入其上下文 |
| 在线 API 复核 | 模型建议与报告 | 所选候选前后文、时间、类型与 A/B 标签 |
| 本地模型复核 | 同上 | 请求回环地址；服务自身联网、日志或回退行为需另行核实 |

本机程序读取文件不等于在线模型已经看到正文，但把文件打开给在线 Agent 看会改变数据边界。A/B 不是匿名化，正文和时间仍可能识别人。报告、工作台、浏览器下载和本机备份也需保管，见[隐私边界](PRIVACY.md)。
