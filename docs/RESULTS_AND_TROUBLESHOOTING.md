# 怎样读结果，以及常见问题

[返回完整流程](WALKTHROUGH.md) · [输入格式](../references/input-format.md) · [审阅规则](../references/review-guide.md)

## 结果对应什么问题

| 文件／数字 | 能回答什么 | 不能说明什么 |
|---|---|---|
| summary.csv／基础 report.html | 某方在指定阶段完整发言交替间隔的平均、中位数、90 分位、长间隔次数及比例 | 不证明对方已读、当时有义务回复或故意拖延 |
| events.csv | 每次完整交替的第一条／最后一条到下一方发言的间隔 | 不等于每条消息被逐一回答 |
| candidates.csv | 阶段主表中，首条口径严格超过候选阈值的记录 | 不等于真实等待计数，不能直接称“恶劣次数” |
| boundary_events.csv | 触及某个阶段，却未完整落在同一阶段的交替 | 不会自动分摊进两个阶段；完全在所设阶段之外的事件不会进入阶段表或边界表 |
| pending.csv | 截止时的最后一段没有后续另一方消息 | 不是一个已完成回复样本，也不确定未来多久回复 |
| context_packet.json／工作台 HTML | 所选候选的前后原文及 ref | 不保证包含整个聊天或全部关键背景 |
| 复核报告／review_summary.csv | 本轮候选的分类、校准起点、理由和可见解释 | 不能推算整个聊天的漏答率、感情投入或意图 |

“A 平均更快”应写成“在这份已取得数据、这段时期、这个口径的完整交替事件中，A 的平均间隔较短”。结合中位数判断典型情况；平均值可能被几次长停聊拉大。样本为 0 时不是 0 秒，比例也不可硬比。

两小时、三小时、四小时阈值互相包含。例如 4.5 小时同时计入三个档位，不是发生了三次。想得到 2–3 小时、3–4 小时等互斥区间，需要相减后明确标注口径。

## 首条与末条为什么不同

虚构例子：A 昨晚说“那先这样”，今天 12:00 又问“投影准备好了吗”，B 12:10 回复。时间戳会把 A 连续发言连在一起；首条口径可能跨夜，末条口径是 10 分钟。上下文支持昨天已经收尾、今天是新问题时，将起点校准到今天的问题，这不是删改数据，而是保留原间隔并增加有证据的解释。

如果 B 的首条消息只是另聊新事，没有回答原问题，程序计量的是“恢复发言”，不一定是“具体问题被回答”。理由中要写明，不能假装已跟踪每个问题最终解决的时间。图片／语音未识别时也不能推测内容。

## 排错：先看提示，不要上传私密文件

| 提示或现象 | 在本机怎样处理 |
|---|---|
| python 找不到／Microsoft Store 提示 | 确认已安装 Python；试 `py -3 --version`；不要把安装问题当成聊天文件问题 |
| CSV 缺少必需列 | 看第一行表头与输入文档；HTML 改扩展名无效；外部工具的 JSON 不一定兼容 |
| UTF-8 解码失败／乱码 | 从导出工具重新选 UTF-8 CSV；不要把加密文件当文本。用编辑器转换编码时另存副本，再重做统计 |
| 方向无效／超过两人／多个会话 | 核对已有可读文件是否只有一个单聊、方向是否明确；不满足则停止，不要删掉第三个人的行来伪造双人会话 |
| 同消息 ID 冲突 | 检查是否拼接了多个不同快照或 ID 其实只是分片局部编号；保留原输入，修正稳定 ID 来源后重新统计 |
| 原始文件指纹／候选边界不符 | 用完全相同的输入与 A/B 映射；编辑、转换、重新导出后需要新一轮统计 |
| 输出目录已存在 | 选新目录名；不要指向原始数据文件夹，不要让程序覆盖之前结果 |
| 没有候选 | 可能确实没有超过阈值的完整事件；检查日期、阶段边界与 pending。无需为得到“有趣结果”降低数据质量 |
| 某月没有记录 | 回手机／电脑核对；可能确实没聊，也可能迁移不完整。本项目不能独立证明完整性 |
| basis_refs／revised_start_ref 错误 | 只选本包真实 ref；起点仅允许 waiting 内消息。retained须严格超过阈值，restart须不超过 |
| 上下文存在截断 | 重新 prepare-review，提高单条上限或选更合适上下文，重新审阅；无法补齐就 uncertain |
| 尚有未审阅事件 | 继续填写，或加 `--allow-partial`；不能把 unreviewed 当作没发生 |
| 工作台填写后刷新丢失 | 页面不自动保存；先下载 JSON。已有下载可用 `review-workbench --reviews`预填到新工作台 |
| 下载 JSON 被改成 txt 或重复后缀 | 在资源管理器显示扩展名，本机更正文件名后将精确路径交给 apply-review；不要把整份结果粘到公开 issue |
| dry-run 成功，API 失败 | dry-run没有连接服务。核对完整端点、密钥与模型、余额和参数支持；检查私密 JSON 的 api_summary 与 uncertain 理由 |
| API HTTP 401／403 | 在本机核对服务与凭据、权限；不要把令牌发给 Agent 或截图到 issue |
| API 404／400 或非 JSON | 地址须为完整兼容端点，确认模型名及 JSON 模式／token 参数支持；不要重定向到另一服务碰碰运气 |
| 本地模型连接失败 | 核对服务已启动、模型已加载、回环端口正确、是否需要认证；HTTP 需 `--allow-local-endpoint` |
| 候选超出字符预算 | 该项未发送。别盲目裁掉关键消息；可改人工或明确增加限制并核实模型上下文容量 |
| 只有少量模型结果 | 查看 max-cases，未选项是未审阅；重跑会重复请求，没有自动断点续跑 |

本仓库不处理数据获取或解密工具的故障，不要把密钥、完整日志、联系人或原始库发到本仓库 issue。报告故障请提供命令结构、Python／系统版本、已去除本机路径和身份的错误文字，以及自己构造的最小虚构数据。

## 发布前再问一次“这是什么文件”

代码目录干净不代表运行产物干净。输入、context_packet、复核工作台、reviews JSON、HTML 报告以及浏览器下载副本都可能包含私人信息。截图也要留意地址栏、资源管理器用户名、文件名与密钥设置。分享时直接使用公开 `examples/` 和 `assets/`，不要拿真实结果仅换个姓名就说已经匿名。
