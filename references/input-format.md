# 输入格式

## 标准CSV

UTF-8或UTF-8 BOM，一行一条消息：

| 字段 | 必需 | 含义 |
|---|---|---|
| timestamp | 是 | ISO时间、常见空格分隔时间，或10位Unix秒/13位Unix毫秒 |
| sender | 是 | 单个会话中的发送者标识；必须恰好两位非系统发送方 |
| kind | 否 | 默认text；system会排除，voice/image等保留为事件，但不自动识别内容 |
| message_id | 否 | 非空且非0时去重；同ID元数据或正文冲突会停止 |
| conversation_id | 建议 | 只允许一个非空会话标识，避免混合多个聊天 |
| text | 统计可省略 | 上下文审阅用的已解析正文；不要放加密内容或原始含密钥的XML |

JSON可以是同字段的消息对象数组，或`{"messages":[...]}`。不支持群聊、多个会话合并或发送方方向未知的数据。

## 中文CSV适配

必需列：`时间`、`是否我发送`、`类型`。方向必须为`是/否`，分别映射A/B。

可选列：`内容`对应text，`server_id`对应message_id，`会话`对应conversation_id。其他列不会自动输出。没有方向时不要猜测发送方。

适配的是可读的导出格式；不是聊天软件数据库或专有备份格式。尚无可读文件时，阅读[数据来源与输入准备](../docs/DATA_PREPARATION.md)，可使用虚构演示或经同意的小样本。本项目不提供提取或解密操作，也不能证明历史完整。已有 JSON 的字段不一定与标准 JSON 相同，不会自动转换。

## 时间与顺序

- 无偏移时间使用`--timezone`；默认+08:00。带偏移时间转换到指定固定偏移。支持UTC和±HH:MM，不处理夏令时规则。
- 统一到秒级；亚秒部分截断。同秒顺序沿用输入的先后并在核对信息中标注，不伪造更细时序。
- 非零消息ID按导出标识去重；不靠正文相似度合并，未提供ID时不会猜测重复。
- 默认首次出现的有效发送方为A，可用`--sender-a`指定。输出不保留原始姓名映射；自己记录映射即可。中文方向字段优先使用明确方向。
- 分阶段采用[start,end)，两个端点都在阶段内的完整交替事件才进入主统计；跨阶段单列。阶段不能重叠。
- 未指定as-of时截止于最后有效消息。只有下一方出现后才是完整交替事件；末尾一轮不充当已完成样本。

## 阈值与含义

首条间隔：对方同一连续发言段的第一条→下一方第一条。

末条间隔：对方同一连续发言段的最后一条→下一方第一条。

严格使用大于：恰好4小时不属于“超过4小时”。多档候选是嵌套的，不可相加。每方比例的分母是同一阶段、同一口径的全部完整交替事件。

连续发言不等于语义上的一轮话题。时间戳仅用于筛选，真实等待与原因需要读上下文。

## 正文和媒体

统计模式不会输出text，也不输出原始姓名、会话名或消息ID。统计脚本仍需在本机读取文件；“不输出正文”不是匿名化保证，时间与阶段名称仍可能敏感。

上下文包显式包含正文片段和稳定ref。图片、语音、视频仅有占位符时，不能从占位符猜内容。对话中的URL不会自动打开；不要把媒体密钥、账号资料或未脱敏的原始导出XML当作text导入。
